# VitaDrive 1.0.0

VitaDrive 1.0.0 is the first production-ready release of the vehicle health
dashboard and API. Since 0.1.0, the project has added safer database
migrations, account security, browser and deployment checks, persistent trip
history, and an offline-capable OBD-II bridge.

## Highlights

### Reliability

- Existing databases are adopted safely and upgraded through reviewed Alembic revisions ([#21](https://github.com/adotak/vitadrive/pull/21)).
- Shared rate limits, query caps, and per-user daily Ask quotas protect the API ([#22](https://github.com/adotak/vitadrive/pull/22)).
- Readings older than 30 days are compacted into daily summaries while trends remain queryable ([#23](https://github.com/adotak/vitadrive/pull/23)).
- Structured logs, request IDs, database health, and consistent error responses improve diagnosis ([#24](https://github.com/adotak/vitadrive/pull/24)).

### Security

- Security headers, CORS controls, Clerk issuer and ownership checks, and dependency auditing strengthen the service ([#25](https://github.com/adotak/vitadrive/pull/25)).
- The dashboard uses native modules and delegated actions, allowing inline script execution to be removed from the CSP ([#27](https://github.com/adotak/vitadrive/pull/27)).

### Quality

- Package typing, mypy, pre-commit checks, and a branch-coverage gate raise the baseline for changes ([#26](https://github.com/adotak/vitadrive/pull/26)).
- Playwright E2E tests exercise dashboard navigation and key vehicle workflows in CI ([#28](https://github.com/adotak/vitadrive/pull/28)).
- Lighthouse CI checks accessibility, best practices, and performance; contrast and image-loading findings were addressed ([#29](https://github.com/adotak/vitadrive/pull/29)).
- Docker builds and a PostgreSQL Compose smoke test cover the container deployment path ([#30](https://github.com/adotak/vitadrive/pull/30)).

### Features

- Trip history persists detected journeys, weekly efficiency summaries, and driving insights ([#31](https://github.com/adotak/vitadrive/pull/31)).
- The OBD-II bridge streams readings with retry/backoff and a persistent offline buffer; `vitadrive obd` remains available for local use ([#32](https://github.com/adotak/vitadrive/pull/32)).

### Developer experience

- Docker Compose provides a documented local PostgreSQL setup and smoke-tested app workflow ([#30](https://github.com/adotak/vitadrive/pull/30)).
- Architecture and contributor guides, ADRs, screenshots, repository templates, and documentation integrity tests make the project easier to review and extend ([#33](https://github.com/adotak/vitadrive/pull/33)).
- Release metadata, upgrade guidance, and version-consistency tests prepare the 1.0.0 release ([#34](https://github.com/adotak/vitadrive/pull/34)).

## Upgrading from 0.1.0

### Database migrations

With the default `VITADRIVE_AUTO_MIGRATE=1`, the first application start opens
the configured database and runs Alembic migrations. If an existing Supabase
PostgreSQL database has the complete legacy application schema but no
`alembic_version` table, VitaDrive stamps it at revision `0001` and applies
revisions `0002` through `0004`, preserving existing rows. The same adoption
path is covered by the PostgreSQL migration tests. A partial legacy schema is
rejected with a clear error rather than stamped. New databases run the
migration chain from its initial revision. If startup migrations are disabled,
apply them manually with `vitadrive db upgrade` before serving the app.

### Optional environment variables

These settings can be added as needed; none are required for a basic local
installation:

- `CRON_SECRET` — bearer secret required by the scheduled `/api/cron/prune`
  endpoint.
- `SENTRY_DSN` — enables optional Sentry error reporting.
- `CORS_ORIGINS` — comma-separated origins allowed to make cross-origin API
  requests; empty disables CORS middleware.
- `ASK_DAILY_QUOTA` — maximum Ask VitaDrive questions per user per UTC day
  (default `50`).
- `LOG_LEVEL` — application log verbosity (default `INFO`).
- `VITADRIVE_RATE_LIMITS` — enables database-backed rate limits by default;
  set to `0` or `false` to disable them.
- `VITADRIVE_AUTO_MIGRATE` — runs migrations at startup by default; set to
  `0` or `false` to disable automatic upgrades.

### Manual security setting

Enable private vulnerability reporting in the repository's GitHub
**Settings → Code security** page. This repository setting cannot be enabled
by a source-code change.

### OBD-II CLI

`vitadrive obd <VIN>` continues to work for local-database bridge mode.
`vitadrive bridge <VIN>` is the new command for streaming readings to a
VitaDrive server, with simulation and offline buffering options.
